Começando com o Forge-SDD

O Forge-SDD é um orquestrador de desenvolvimento que conecta você e sua IA num fluxo de trabalho claro: você decide, a IA implementa, você aprova.

1. Instalação e setup

O forge init faz perguntas interativas sobre o projeto (nome, stack, banco). Se a sua IA faz o setup por você, use o prompt abaixo — ele coleta essas respostas antes de rodar o comando, sem travar em prompts interativos.

Prompt para IA 
Quero instalar o forge-sdd aqui. Me ajude a configurar.

Primeira pergunta: o que você está construindo?
Descreva com suas palavras — pode ser simples, ex:
"um app de agendamentos", "uma API para meu e-commerce", "um script que lê planilhas".

Com base no que você me contar, vou sugerir a melhor configuração
seguindo boas práticas de mercado e confirmar com você antes de rodar.

Depois da confirmação, instale assim:
npm install -g @nathanramorim/forge-sdd
forge init --yes --name "[nome]" --stack [stack] --db [db] --agent [agente]

Se preferir instalar agora com configuração padrão e ajustar depois,
responda apenas: padrão

2. Defina as regras do projeto (/constitution)

Antes da primeira feature, você precisa registrar as decisões invioláveis do projeto: qual banco usar, como nomear branches, se usa ORM ou SQL direto, qualquer escolha que a IA não deve questionar. Essas regras formam a Constitution — um arquivo que todos os agentes leem antes de trabalhar.

Sem a Constitution, a IA toma decisões arbitrárias que você vai reverter mais tarde. Com ela, cada feature nasce alinhada com o que você decidiu.

Exemplo de instrução para a Constitution:

Nunca use ORM; acesso a banco sempre via SQL direto com prepared statements.
Branches de feature seguem o padrão feat/[número]-[nome-curto].
Prompt para IA 
Vamos definir as regras do projeto com /constitution.
Execute /constitution e me ajude a cadastrar as primeiras decisões arquiteturais.
Comece me fazendo as 3 perguntas mais importantes para este tipo de projeto:
quais são as decisões que mais causam atrito se não forem definidas logo no início?

3. Primeira feature

Com o setup e a Constitution no lugar, peça à IA para criar a primeira feature. Ela vai rodar o discovery, montar um plano e aguardar sua aprovação antes de escrever uma linha de código.

Prompt para IA 
Vamos criar a primeira feature com o forge-sdd.
Execute /discovery [descreva aqui o que você quer construir].
Me mostre o plano antes de implementar.

Jornada ideal

O Forge-SDD organiza o trabalho em três papéis simples. Você não precisa saber programar — só precisa tomar decisões.

1

Discovery

Você descreve o que quer. A IA analisa o projeto, levanta riscos e monta um plano detalhado. Você lê e decide se faz sentido.

2

Builder implementa

Depois da sua aprovação, a IA segue exatamente o plano: escreve o código, cria os testes e prepara tudo para você conferir.

3

Você aprova

As mudanças chegam sem surpresas. Você confere o que foi feito e aprova. Se não estiver bom, a IA corrige até ficar.

Exemplos práticos

Veja como adicionar uma feature real do início ao fim.

Adicionar comando forge greet

Neste exemplo, vamos adicionar um comando que imprime "Olá, mundo!" no terminal.

  1. Inicie o discovery.

    Mande o prompt abaixo para sua IA:

    Prompt para IA 
    Inicie o discovery para: adicionar comando forge greet
Execute /discovery e me mostre o plano antes de implementar.
  2. Aprove o plano.

    A IA vai mostrar o que pretende criar. Se estiver certo, diga "aprovado" ou "pode implementar".

  3. Revise o PR no GitHub.

    Quando a IA terminar, ela abre um PR com o código. Você revisa o diff e faz o merge.

Hub mode — um forge para vários repos

Em vez de rodar forge init em cada repo separado, você elege um repo como hub e os outros como satélites. O hub rastreia o status de todos os projetos do time em um único lugar.

Passo a passo

  1. Inicialize o repo hub.

    No repositório que será o hub central, rode:

    forge init
  2. Vincule os repos satélites.

    Para cada repo do time que você quer rastrear:

    forge init --link ../outro-repo
  3. Veja o status de todos.

    No repo hub, rode forge pipeline para ver o estado de cada repo vinculado:

    forge pipeline
Prompt para IA 
Configure o forge-sdd como hub neste workspace.
O repo atual é o hub. Para cada repo satélite, rode:
forge init --link <caminho-do-repo>
Me diga quando terminar e mostre os repos vinculados.
Prompt para IA 
Liste todos os repos vinculados ao hub e o status de cada um:
forge pipeline
Mostre quais têm features abertas e quais estão sem atividade.

Quadro de acompanhamento (opcional)

em construção, ainda não disponível

Um painel em colunas, no GitHub Project, que espelha em que etapa está cada trabalho. Está especificado e aprovado, mas ainda não foi construído. Hoje o quadro é mantido à mão.

  • É opcional e vem desligado. Sem ele, os mesmos passos acontecem só nos arquivos e nada é consultado no GitHub.
  • O arquivo é a fonte da verdade; o quadro é só um espelho.
  • São 7 colunas: Backlog, Spec, Spec-validation, Todo, Building, Validation e Done.
  • Em cada passo fica claro o que é HUMANO, o que é IA e o que é AUTOMÁTICO.
  • Arrastar um cartão é um pedido: abre um menu e nada muda sem a sua confirmação.
  • Dois interruptores: "Quadro de acompanhamento" e "Início automático do Builder". Os dois vêm desligados.
  • Ligar custa chamadas ao GitHub e, no início automático, um processo local. Desligado, o custo é zero.
  • Item só de adr, rule ou documentação segue pela via rápida, de Todo direto a Validation.

Guia completo: docs/quadro-do-ciclo.md. O link só funciona depois do merge da iniciativa 108.
