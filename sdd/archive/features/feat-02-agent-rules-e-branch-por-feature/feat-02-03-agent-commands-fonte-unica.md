# Feature 02-03 — `.agent/commands/` — Corpo Canônico por Comando e Adaptadores Finos

Maior superfície do pacote: toca os 12 comandos SDD × 3 agentes (~36 arquivos hoje divergentes, confirmado comparando `discovery.prompt.md.tmpl` dos três agentes na discovery). Elimina a duplicação de conteúdo — não as pastas por agente, que continuam existindo por restrição de cada ferramenta (`.claude/commands/`, `.gemini/prompts/`, `.github/prompts/`).

## Critérios de Aceitação Executáveis

1. Para cada um dos 12 comandos SDD, existe um corpo canônico único em `internal/scaffold/templates/.agent/commands/<comando>.md.tmpl` — a instrução completa, agnóstica de ferramenta.
2. Os templates hoje divergentes em `.claude/commands/`, `.gemini/prompts/`, `.github/prompts/` são reescritos como adaptadores finos: mantêm só o frontmatter/sintaxe de invocação obrigatórios daquela ferramenta (ex: `description`/`agent`/`${input:...}` do Copilot) e, no corpo, instruem a ler `.agent/commands/<comando>.md` para a instrução completa.
3. **A descoberta do comando (`/discovery`, `/status`, etc.) não pode regredir em nenhum agente.** Cada ferramenta lista seus comandos pelo **nome do arquivo dentro da sua própria pasta** (`.claude/commands/<comando>.md` → `/comando` no Claude; mesma lógica em `.gemini/prompts/`; `.github/prompts/` usa o frontmatter `description`/`agent` para o menu do Copilot) — isso não muda. O adaptador fino preserva nome de arquivo e localização; só o corpo é substituído pelo ponteiro. Onde a ferramenta suportar metadado de descrição (Copilot já usa; Claude/Gemini suportam frontmatter opcional), o adaptador mantém esse campo, já que é metadado específico da ferramenta, não conteúdo compartilhado.
4. Validação de não-regressão: comparar, comando a comando, a cobertura de conteúdo do adaptador antigo (corpo completo) vs. par novo (adaptador fino + corpo canônico) — nenhum comportamento documentado hoje é perdido; e confirmar manualmente em cada agente que `/comando` continua aparecendo/funcionando no autocomplete/menu.
5. Implementação começa por um comando piloto (`/discovery`, já auditado na discovery desta feature) antes de converter os outros 11, para validar o padrão de adaptador fino na prática antes de escalar.
6. `go build`, `go vet ./...` e `go test ./...` passam; golden fixtures de `internal/scaffold` regeneradas cobrindo `.agent/commands/` e os adaptadores finos dos três agentes para os 12 comandos.

## Status: done

Criados os 13 corpos canônicos em `internal/scaffold/templates/.agent/commands/*.md.tmpl` (archive, c4-architecture, constitution, discovery, doctor, nova-feature, novo-fix, proxima-feature, revisar, split-features, status, tutorial, upgrade-sdd), baseados no conteúdo até então mantido em `.claude/commands/` (a versão mais enxuta entre os três agentes). Os adaptadores de `.claude/commands/`, `.gemini/prompts/` e `.github/prompts/` (12 comandos cada — Copilot nunca teve `c4-architecture`, gap pré-existente fora de escopo) foram reescritos como ponteiros finos: Claude/Gemini mantêm só o cabeçalho `# Prompt: <nome>` + instrução de leitura; Copilot preserva seu frontmatter (`description`/`agent`) original e aponta para o mesmo corpo. Nome de arquivo e localização (o que cada ferramenta usa para o autocomplete `/comando`) não mudaram — validado manualmente inspecionando os arquivos gerados. Golden fixtures regeneradas; dogfood deste repositório (`.claude/`, `.gemini/`, `.agent/`) atualizado via `forge-sdd update --version 2.2.0-beta`.
